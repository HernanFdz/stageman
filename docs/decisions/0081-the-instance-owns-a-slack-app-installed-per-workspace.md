# 0081 — The instance owns a Slack app, installed per workspace

## Status

Accepted. The Slack half of what
`docs/decisions/0076-a-credential-is-guided-in-and-checked-before-it-is-kept.md`
looked for and found half of, and the second app the Instance page of
`docs/decisions/0077-a-repository-is-reached-through-an-app-the-instance-owns.md`
was named to hold. Amends four records without reversing any:
`docs/decisions/0029-a-reply-is-routed-by-its-thread.md`, whose rejection of
one app for the whole instance stands for an app a project owns and is
reversed for an app the instance owns, since the concentration it refused
arrived through 0077 on the platform's side and is accepted here on the same
terms; `docs/decisions/0059-a-project-speaks-and-listens-on-slack-always.md`,
whose binding is still two credentials that never travel together, now held
by the app and by the workspace rather than both by the project;
`docs/decisions/0060-a-binding-is-a-workspace.md`, whose "the project a
message belongs to is the socket it arrived on" becomes the socket, then the
workspace, then the room, and whose one-app-per-project must narrows to an
app a project owns; and
`docs/decisions/0063-another-app-is-heard-in-a-watched-room.md`, whose tools
take no room, which they now may from the foreman's own room and nowhere
else. Answers the open question on Slack's setup being one redirect, as far
as the platform lets it be. Builds on
`docs/decisions/0078-a-repository-is-chosen-from-what-its-access-reaches.md`
for the shape of an install that comes back under a state.

## Context

Every project is bound to a Slack app of its own, per 0029 and 0060, and
the reasons were measured: one app-level token opens one event stream, two
connections on one app split the stream between them, and an app is created
by a person on the platform's site. So creating a project costs creating a
Slack app: a manifest pasted, an install pressed, a bot token copied, an
app-level token generated by hand and copied. Ten minutes the first time and
five every time after, for every project, and the one thing the platform
never says is which step was skipped.

0077 removed the same cost on the platform's side by giving the instance an
App of its own that a project installs, and 0078 gave the install a shape: a
press mints a state, a tab goes to the platform and comes back under it, and
the form learns of the return through the tick. What Slack offers was checked
against its documentation on 2026-09-25 rather than remembered, and five
things decide the shape.

**An app is created by a person, or by an API that costs a person as much.**
The manifest API creates an app from a manifest and answers with its client
identifier, client secret, verification token and signing secret. It is
called with a configuration token that a person generates on the site, that
lives twelve hours, that is refreshed with a refresh token whose own lifetime
the documentation does not state, and that the platform marks as beta. The
app-level token that opens the event stream is generated on the app's own
page and by no API, whichever way the app was made. So the API saves
nothing: a configuration token is a paste as the client pair is, and the
app-level token is a paste either way.

**An install is a redirect, and the redirect reaches this instance.** The
platform's authorisation address takes the app's client identifier, the bot
scopes, a state and a redirect address; a person chooses a workspace and
allows; the browser comes back to the redirect address with a code, good for
ten minutes, and the state; one request with the client identifier and
secret converts the code into the workspace's bot token, the workspace's
identifier and name, the bot's user identifier and the app's. The
documentation says a redirect address must use HTTPS and lists every plain
address as bad. The app's settings accepted an address on localhost with a
plain scheme on 2026-09-23, and on 2026-09-25 the authorisation step honoured
one: the operator's browser was brought back to this instance on localhost
with the code and the state. So a laptop instance can take the install
redirect.

**One connection hears every workspace.** An app-level token is the app's
across every workspace it is installed in, and one connection opened with it
is sent every workspace's events; the platform allows ten connections at
once and shares the events among them with no pattern, which is the halving
0060 measured. Every event says which workspace it is from, inside its
payload rather than on the envelope, measured in all fifteen envelopes
recorded on 2026-09-15: as the payload's own *team_id*, as its
*context_team_id* and under its *authorizations*. So one connection per
app-level token is the design, and a message's workspace is read off the
frame.

**Installing on the app's own workspace needs nothing more; a second
workspace needs one press on the platform.** An app installs on the
workspace that created it by this flow with nothing else; any other
workspace needs public distribution activated on the app's page, once,
unlisted and unreviewed, and the platform's checklist for it says the
redirect addresses must be SSL. Whether it refuses an address on localhost
was not measured, and is a revisit trigger below.

**The client pair cannot be checked before it is kept.** Measured on
2026-09-25: the exchange answers *invalid_code* before it looks at the client
identifier or the secret, so a bogus code cannot tell a right pair from a
wrong one. The app-level token can be checked as a binding's is today, by
asking where to connect.

What a shared app costs was weighed rather than assumed. 0029 rejected one
app for the instance as a credential concentration; the instance already
holds every project's app-level token in one process, and 0077 put one key
for every installation in the same file, so the argument now weighs one
sealed secret against one per project in the same file. 0029 also counted a
distinct bot per project as a legibility win; with one app every project
speaks as the same bot, and the project's name is in every room's name since
0061, and each foreman has a room of its own since
`docs/decisions/0067-a-transcript-is-posted-where-its-speaker-owns-the-room.md`.

## Decision

**The instance owns one Slack app, registered from the Instance page by
pasting three values; a workspace installs it by the platform's redirect,
and is kept beside the app; a project speaks and listens through a workspace
of that app, or through an app of its own as it does today; one connection
per app-level token hears every workspace; and a message is routed by its
workspace and then by the room it was said in.**

- **One app per instance, registered by pasting three values.** The
  Instance page links the platform's form with the manifest filled in, as
  the guide of 0076 does on the project form today, the manifest now
  carrying the address the redirect comes back to, composed from this
  instance's own address. The operator creates the app, generates the
  app-level token by hand under Basic Information, and pastes the client
  identifier, the client secret and the app-level token. The app-level token
  is checked before it is kept, by asking where to connect, as a binding's
  is; the client pair is kept unchecked, since it cannot be, and the page
  says so: the first install is its check, and a pair the platform refuses
  there is said on the tab with the platform's word. Not the signing secret,
  which verifies requests this instance never receives, since nothing
  arrives over HTTP under Socket Mode; and not the verification token, which
  the platform deprecated. A secret kept for nothing is a secret to leak for
  nothing, per 0077. The app is forgotten from the page, and refused while a
  project speaks through a workspace of it; the registration on the platform
  is the operator's to delete.

- **A workspace is where the app is installed, learned from the redirect
  and kept beside the app.** *Install on a workspace* opens the platform in
  a tab of its own, by script, with a state minted for the press and held,
  per 0078. The platform brings the tab back to a path of this instance's
  own with a code and the state; the instance holds the browser's request,
  exchanges the code with the client pair, and keeps the workspace under the
  app before the tab is answered: its identifier and name, the bot's user
  identifier, and the bot token, sealed as every credential is. The landing
  page closes the tab, the write is the tick, and the form that pressed asks
  what came back under its state and moves onto it. An install on a
  workspace already kept refreshes its record. The Instance page lists the
  workspaces, each forgettable while no project speaks through it. A state
  nobody minted keeps the workspace and leaves the tab open saying to press
  again, as an installation does; an exchange the platform refuses keeps
  nothing and says why on the tab.

- **A binding is one of two shapes, and the Slack card is the enum.** A
  project speaks and listens through a workspace of the instance's app, or
  through an app of its own with both tokens pasted, as every project does
  today. The card's control is a sentence saying which shape the project is
  in, with the actions inline, on the pattern 0078 set for the GitHub card:
  *install it on a workspace*, *use an app of its own*, *go back*. An app of
  its own is set in a panel of two boxes, checked there, and never shown
  back. Creating and amending are one form, so a project written before
  this record can be moved onto the instance's app from its settings, and
  back. Every project still needs a binding, per 0059, in either shape. A
  job's handout carries the workspace's bot token exactly as it carries a
  binding's own today, and the app-level token never enters a container,
  whichever app it belongs to.

- **One connection per app-level token, and a message is routed by its
  workspace and then by its room.** The instance listens once for its own
  app, however many workspaces it is installed on and however many projects
  speak through them, and once per project with an app of its own, as
  today. A frame says its workspace in its payload, and the projects bound
  to that workspace are the candidates; among them the room decides, as it
  does today. A job's room is that job's, a foreman's room and a watched
  room are that project's foreman's, and a room no project owns is the
  foreman's of the workspace's only project when there is one. Where
  several projects share a workspace, a person's mention in a room none of
  them owns is answered where it was said with a notice naming each
  project's foreman room, and costs no turn; an app's message there is
  nobody's, as it is today. Who this instance is on a workspace is asked
  with that workspace's bot token, per workspace, as it is asked per binding
  today, since each install has a bot user of its own.

- **A room in a shared workspace is watched from the foreman's own room,
  naming it.** With one project in a workspace, asking in the room works as
  0063 decided. With several, a mention in the room reaches nobody but the
  notice, so the ask is made in the project's foreman room, naming the room
  the way the platform spells a room in a message. The tools of 0063 take
  that room only when the turn was asked in the foreman's own room, and
  refuse it from anywhere else, so that a foreman still cannot be talked
  into watching a room from a room it was not asked in by a person. A
  watched room belongs to one project: a second project's ask is refused,
  naming the first.

- **An app a project owns is one project's.** Two projects pasting the same
  app of their own would each hear half of what is said, per 0060; a binding
  whose bot identity another listening binding already has is refused when
  it is checked, naming the project.

- **The Instance page carries the second app.** Beside the GitHub App, the
  Slack app: the paste form until one is registered, then its name on the
  platform, the workspaces it is installed on, *Install on a workspace*, and
  *Forget*. The page says which press on the platform a second workspace
  needs, and where.

Rejected: **creating the app from the dashboard by the manifest API.** A
configuration token is generated on the site and lives twelve hours, the
app-level token is generated on the site whichever way the app was made, and
the API is beta: two pastes and a clock instead of three pastes, for a step
taken once per instance.

Rejected: **keeping the signing secret and the verification token**, for the
reason the decision gives.

Rejected: **a home room per project for routing a shared workspace's
unowned mentions.** 0061 took the address away deliberately, and a claimed
room is the address back under another name; the notice names the rooms that
already exist.

Rejected: **routing an unowned mention to every project's foreman.** A turn
per project per message, and as many answers.

Rejected: **the Events API**, again, for 0029's reason: a daemon on a laptop
has no public address.

Rejected: **pasting a workspace's bot token under the instance's app**, as a
second way in. The redirect reaches a laptop, measured, and a shape with two
ways in is two forms to keep honest.

Rejected: **keeping one app per project as the only shape.** It is what
exists and works, and it is the ten minutes per project this record removes.
Kept as a shape, because the projects that have one keep working and because
it is the escape hatch for a workspace the instance's app cannot reach.

## Consequences

**The channel crate renders two more requests and reads two more answers**:
the authorisation address for a press, and the exchange of a code, whose
answer carries the bot token, the workspace's identifier and name and the
bot's user identifier; and it reads a frame's workspace, which it did not
decode before. The manifest it carries gains the redirect address, composed
at the edge from the instance's address.

**The file grows and bridges.** The Slack app beside the GitHub App: its
client identifier in the clear, its client secret and app-level token
sealed, and its workspaces under it, each with its identifier, name, bot
user and sealed bot token. A project's Slack binding is one of two shapes on
disk, the bare pair the last release wrote opening as an app of its own.
Opening refuses a project naming a workspace the app does not hold, as it
refuses an installation the App does not hold.

**The instance holds more and listens differently.** Installs begun, by
state; exchanges being answered; and one listener per app-level token
rather than per project, each knowing which workspaces it hears and who
this instance is on each. A restart begins with none of these and listens
again from what the file says.

**The handout is unchanged in shape**: a binding's speaking half, resolved
through the app where the project speaks through a workspace.

**The wire says the shapes**: the Slack app as a page may know it, never its
secrets; its workspaces; a binding draft as one of two shapes, with a
workspace named by the state its tab came back under or the one the project
holds; and the refusals that name the app, the workspace or the pair.

**Two pages change and one path is added.** The Instance page's Slack card;
the project form's Slack card as the sentence; and the instance answers one
more path of its own, where the platform brings the tab back.

**The tools change in one place**: the watching tools take a room from the
foreman's own room.

**Vocabulary gains a word**, **workspace**, in `docs/conventions.md` §2, and
the rule in §3 that every project has a Slack app of its own becomes a rule
about the app a project owns.

**Scenarios pin**: an app registered from the page with its app-level token
checked and kept, and refused with the platform's word; an install come back
under a state, exchanged, kept under the app and named under the state, with
the tab closed; a state nobody minted keeping the workspace with the tab
staying; an exchange the platform refuses; a project created on the
workspace its tab brought back, and one moved onto it from an app of its
own; the app and a workspace refused forgetting while used; one connection
routing two workspaces' messages to their projects; a mention in an unowned
room answered with the notice where several projects share the workspace
and handed to the foreman where one does; a room watched from the foreman's
room, refused from elsewhere, and refused for a second project; a daemon
dying mid-exchange keeping nothing; and the older file opening with a bare
binding.

**`README.md` says what an operator does**, once per instance and once per
workspace, and the manifest it carries changes.

**Reversing** is the app and its workspaces dropped from the file and every
project moved back onto an app of its own, which is the ten minutes per
project this record removes, paid once more.

**Revisit if** the platform adds an API for app-level tokens, which is when
registration becomes a redirect as the App's is; if activating distribution
is found to refuse a redirect address on localhost, which is when a second
workspace needs a domain-hosted instance and the page has to say so; if a
configuration token stops expiring, which reopens the manifest API; if a
workspace is found holding so many projects that the notice reads as noise,
which is when a room wants a claim after all; or when a second person
operates one instance, which is when a workspace that came back under a
state should be that person's rather than the page's, as 0078 already says
of an installation.
